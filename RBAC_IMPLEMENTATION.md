# Реализация системы RBAC (Role-Based Access Control)

## Обзор

В проект была внедрена полноценная система управления ролями и правами доступа (RBAC) для обеспечения безопасности и контроля доступа к функциональности приложения.

## Модель ролей и разрешений

### Роли

1. **guest** (Гость)
   - Неавторизованный пользователь
   - Разрешения: нет

2. **user** (Пользователь)
   - Обычный зарегистрированный пользователь
   - Разрешения:
     - `files.view_own` - просмотр своих файлов
     - `files.upload` - загрузка файлов
     - `files.delete_own` - удаление своих файлов
     - `censor.use` - использование цензурирования

3. **admin** (Администратор)
   - Полный доступ ко всем функциям
   - Разрешения:
     - Все разрешения роли `user`
     - `files.view_all` - просмотр всех файлов
     - `files.delete_all` - удаление любых файлов
     - `users.view` - просмотр списка пользователей
     - `users.manage` - управление пользователями
     - `users.delete` - удаление пользователей

### Разрешения (Permissions)

Разрешения организованы по ресурсам и действиям:
- **files**: `view_own`, `view_all`, `upload`, `delete_own`, `delete_all`
- **censor**: `use`
- **users**: `view`, `manage`, `delete`

## Backend реализация

### Модели данных

1. **Role** (`backend/models.py`)
   - `id` - уникальный идентификатор
   - `name` - название роли
   - `description` - описание роли
   - Связь many-to-many с `User` и `Permission`

2. **Permission** (`backend/models.py`)
   - `id` - уникальный идентификатор
   - `name` - название разрешения (например, `files.upload`)
   - `description` - описание разрешения
   - `resource` - ресурс (files, users, censor)
   - `action` - действие (view, upload, delete, etc.)
   - Связь many-to-many с `Role`

3. **User** (расширен)
   - Добавлена связь many-to-many с `Role`
   - Методы `has_role()` и `has_permission()` для проверки прав

### Сервисы

1. **RBACService** (`backend/rbac_service.py`)
   - Инициализация ролей и разрешений
   - Назначение/удаление ролей пользователям
   - Проверка прав доступа
   - Получение списка ролей и разрешений

2. **Auth** (расширен `backend/auth.py`)
   - `require_permission(permission_name)` - dependency для проверки разрешения
   - `require_role(role_name)` - dependency для проверки роли
   - `require_admin` - dependency для проверки администратора
   - Обновлен `get_current_user` для возврата ролей пользователя

### Endpoints

#### Защищенные endpoints с проверкой прав:

- `POST /upload` - требует `files.upload`
- `POST /upload-multiple` - требует `files.upload`
- `GET /files` - требует `files.view_own`
- `DELETE /files/{object_name}` - требует `files.delete_own` или `files.delete_all`
- `POST /censor/pixelate` - требует `censor.use`

#### Административные endpoints:

- `GET /admin/roles` - получение всех ролей (требует admin)
- `GET /admin/permissions` - получение всех разрешений (требует admin)
- `GET /admin/users` - получение списка пользователей (требует `users.view`)
- `GET /admin/users/{username}/roles` - получение ролей пользователя (требует admin)
- `POST /admin/users/{username}/roles/{role_name}` - назначение роли (требует admin)
- `DELETE /admin/users/{username}/roles/{role_name}` - удаление роли (требует admin)

## Frontend реализация

### Типы и интерфейсы

- Обновлен интерфейс `User` в `frontend/src/types/auth.ts`:
  - Добавлено поле `roles?: string[]`

### Компоненты

1. **RoleProtectedRoute** (`frontend/src/components/Auth/RoleProtectedRoute.tsx`)
   - Компонент для защиты маршрутов на основе ролей
   - Поддерживает проверку одной или нескольких ролей
   - Автоматически предоставляет доступ администраторам

2. **UserManagement** (`frontend/src/pages/UserManagement.tsx`)
   - Страница управления пользователями (только для администраторов)
   - Просмотр всех пользователей и их ролей
   - Назначение и удаление ролей
   - Просмотр доступных ролей и их разрешений

### Хуки

**usePermissions** (`frontend/src/hooks/usePermissions.ts`)
- `hasRole(roleName)` - проверка наличия роли
- `hasPermission(permissionName)` - проверка наличия разрешения
- `hasAnyRole(roleNames)` - проверка наличия хотя бы одной роли
- `hasAllRoles(roleNames)` - проверка наличия всех ролей
- `isAdmin` - проверка администратора
- `userRoles` - список ролей пользователя

### Адаптация UI

1. **Header** (`frontend/src/components/Layout/Header.tsx`)
   - Добавлена ссылка "Управление" для администраторов
   - Отображается только при наличии роли `admin`

2. **RedactionPrototype** (`frontend/src/components/RedactionPrototype/RedactionPrototype.tsx`)
   - Кнопки загрузки и цензурирования блокируются при отсутствии прав
   - Кнопки удаления файлов отображаются только при наличии права `files.delete_own`
   - Подсказки о недостающих правах

## Инициализация

При первом запуске приложения автоматически:
1. Создаются таблицы для ролей и разрешений
2. Инициализируются стандартные роли и разрешения
3. Создаются демо-пользователи:
   - `admin` / `secret123` (роль: admin)
   - `user` / `secret123` (роль: user)

Новые пользователи автоматически получают роль `user` при регистрации.

## Безопасность

1. **Backend проверки**: Все проверки прав выполняются на сервере
2. **403 Forbidden**: При недостатке прав возвращается статус 403
3. **JWT токены**: Роли включены в токен через данные пользователя
4. **Frontend защита**: UI адаптируется под права, но не является единственной защитой

## Тестирование

Для тестирования системы:

1. Войдите как `admin` / `secret123`:
   - Должен быть доступ ко всем функциям
   - Должна быть видна ссылка "Управление" в меню
   - Можно управлять ролями других пользователей

2. Войдите как `user` / `secret123`:
   - Доступ к загрузке и цензурированию файлов
   - Можно удалять только свои файлы
   - Нет доступа к управлению пользователями

3. Выйдите из системы (guest):
   - Нет доступа к защищенным страницам
   - Можно только просматривать публичную информацию
